## Conventions

**Devices** (per test-strategy matrix): **LA** low-end Android (2–3 GB RAM) · **MA** mid/high Android · **IS** iPhone Safari (Web build) · **DC** desktop Chrome (Web build). **AE** Android emulator (mock GPS only). "All" = LA, MA, IS, DC.

**Type:** `manual` · `automated-widget` (Flutter widget/unit test, written by devs, QA reviews) · `automated-db` (SQL test against Supabase local, written by supabase-dev).

**Priority:** P1 = blocks the sprint goal or a legal/privacy rule · P2 = important behaviour · P3 = edge case / polish.

**Mock GPS points** (from SPEC-001 §8). **Entry criterion (Q-QA-23):** before the first E1 test run, QA verifies every point against the seeded data with supabase-dev (density at MP-2, 0 lots ≤ 1 km and ≥ 1 lot ≤ 3 km at MP-5, 0 lots ≤ 3 km at MP-7, ≥ 2 lots with identical coordinates). E1 execution does not start until this is recorded.

**Service area (BR-12):** lat 10.30–10.45, lng 107.03–107.20, edges **inclusive**.

**Test data:** local-only seed owned by supabase-dev (SPEC-001 §8): ≥ 60 lots around MP-2, mix of `motorbike` / `car` / both, 0 lots within 1 km of MP-5, ≥ 1 within 3 km of MP-5, 0 lots within 3 km of MP-7, ≥ 2 lots with identical coordinates. A separate 5,000-lot generated local dataset for the NFR-2 DB performance check.

**Tools:** Android: Developer options → mock location app, `adb logcat`, Charles/mitmproxy or Android Studio Network Inspector, `adb shell run-as` (debug build) for SharedPreferences. Web: Chrome DevTools (Sensors → Location override, Network, Application → Storage, Console), Safari Web Inspector via Mac for IS. Network throttling: DevTools "Fast 4G" / Android emulator network profile. Firebase DebugView on a debug build with collection force-enabled (NFR-6).

**Fresh install** = Android: uninstall + reinstall (or Clear storage). Web: clear site data (storage + permissions) for the origin.

**Session** = until app restart (Android: process killed and relaunched) / page reload (Web).
