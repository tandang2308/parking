**How the run was set up**
- **Mock GPS with accuracy.** `adb emu geo fix` always reports `hAcc = 5 m`. So I used the Android shell test providers instead: `cmd location providers add-test-provider gps|fused` and `set-test-provider-location … --accuracy <m>`. A small loop re-sent the position every second. This gave fixes with any accuracy (10 / 100 / 101 / 150 m). Afterwards I removed the test providers and restored the mock-location app-op.
- **Network.** To read request bodies, I ran a small local logging reverse proxy on the test PC: device `:55321` → proxy `:55399` → Kong `:55321`. It logged only the method, the URL and the body of `/rpc/` calls, never headers or keys. After the run I set `adb reverse` back to `tcp:55321 → tcp:55321`. "Body" below means a line from this proxy log, for example `POST /rest/v1/rpc/nearby_lots BODY={"lat":10.3486,"lng":107.0833,"radius_m":1000,"vehicle_type":null}`.
- **Logs.** "Log" means the app line `nearby_lots loaded count=… radius_m=… trigger=…` from `adb logcat`.
- **Distances.** I checked card distances with my own haversine against the lot coordinates in the local DB (read-only `select`).

## 3. Bugs

### BUG-1 — "Not now" on S1 (opened from My location) clears the manual position and reloads at the default centre
- **Reference:** TC-1.3.15 run a; US-1.3 AC4 (Q-QA-18); BR-8; BR-11.
- **Severity:** Major. A user without location consent loses their manual position and its distances by tapping My location and then "Not now". AC6 says this user group can rely on a manual position.
- **Steps to reproduce:**
  1. Fresh install, S1 → "Not now" (banner "Turn on location to see lots near you" + Enable).
  2. ⋮ → "Set my position" → move the map → "Confirm". The manual marker is shown and lots load around it.
  3. Tap "My location". S1 opens.
  4. Tap "Not now".
- **Expected (AC4):** "Tapping 'My location' switches back to GPS … **only if** permission is granted and location services are on; **otherwise the manual position stays active** and 'My location' runs the same action as the current banner". TC-1.3.15: "Manual position stays active (marker unchanged, no reload)".
- **Actual:** After step 4 the manual marker is gone. A new `nearby_lots` call goes to the default centre (`{"lat":10.346,"lng":107.074,"radius_m":1000}`, `count=19`). The map is back at the default view, and a tapped card has **no distance** (no user position). Steps 1–3 work as expected (S1 opens, no toast, no request). The widget test `AC4 / TC-1.3.15a` only checks the state while S1 is open, not after "Not now".
- **Screenshots:** `26-tc1315a.png` (S1 open), `27-tc1315a-back.png` (after "Not now"), `28-tc1315a-repro-card.png` (card without distance, 2nd reproduction).

## 4. Observations

- **O1 (test environment):** On every cold start the first streamed fix came after the 10 s timeout. The app then took the US-1.1 AC9 path: last-known + "Locating…" (`02-after10s.png`). Fixes did arrive later. This is probably the emulator / Google Play fused provider with shell test providers, not the app. It needs a check on a real device.
- **O2 (AC5):** After Cancel the camera stays where the user dragged it. It does not go back to the view before adjust mode. Position, pins and requests are unchanged, as AC5 asks. See Q1.
- **O3 (UX, Minor):** In adjust mode, pins and clusters are drawn **on top of** the crosshair pin. In `11-tc132-adjust.png` a "2" cluster partly covers it. The manual marker also uses nearly the same dark slate colour as cluster circles, so the two can be confused when they overlap.
- **O4 (AC4 / US-1.1 AC9):** When switching back to GPS with no live fix but a last-known < 5 min, the app shows "Locating…" and loads around the last-known **immediately**, not after 10 s. This matches BR-8 (last-known is the current position), but differs from the wording "if … no fix arrives within 10 s, US-1.1 AC9 applies". With no last-known the app waits the full 10 s ✓.
- **O5 (info):** If the user taps My location (manual active, permission denied once) and then **grants** the OS dialog, the manual position stays active, with no toast and no request. A second tap on My location switches to GPS with the toast. This fits AC4 (checked at tap time), but see Q2.
- **O6 (info):** In the TC-1.3.15b run, Android pre-selected "Approximate" in the permission dialog because of the earlier TC-1.3.1b grant. Testers should watch the Precise/Approximate toggle.
- **O7 (info):** The out-of-area banner after a manual position outside the area shows "Go to Vũng Tàu" and works. The manual marker stays outside, as expected.

## 5. Open questions

- **Q1 (AC5):** Should Cancel also put the camera back where it was before adjust mode started? Today the map stays where the user dragged it (O2). The spec covers only position, pins and requests.
- **Q2 (AC4):** When the user grants permission from the dialog that My location opened (manual position active), should the app switch to GPS at once? Today a second tap is needed (O5).
- **Q3 (AC4 / AC9 wording):** Is an immediate last-known load after "My location" (O4) the intended behaviour, or should the 10 s wait apply before last-known is used?
- **Q4 (marker colour):** PO to confirm the dark slate manual marker. Should it be visually more distinct from cluster circles (O3)?
