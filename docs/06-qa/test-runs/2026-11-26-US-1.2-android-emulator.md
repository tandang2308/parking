## 3. Bugs

### BUG-1 — After "Expand to 3 km" the found lots are outside the viewport; the user sees an empty map and no message
- **Reference:** TC-1.2.3 step 2; US-1.2 AC4; BR-1.
- **Severity:** Major (UX). At an empty spot, Expand looks as if it did nothing. This may be a spec gap rather than a code bug (see Q1).
- **Steps to reproduce:**
  1. `adb emu geo fix 107.1150 10.3400` (MP-5). Permission granted.
  2. Open the app. "No parking lots within 1 km" + "Expand to 3 km" is shown.
  3. Tap "Expand to 3 km".
- **Expected (TC-1.2.3):** "2: same search point, body `radius_m: 3000`; **≥ 1 pin shown**; message gone." The spec (AC4) says: "after expanding, the same search is repeated with `radius_m = 3000`."
- **Actual:** The log shows `nearby_lots loaded count=7 radius_m=3000 trigger=position` and the message disappears. But the camera stays at zoom 16 on MP-5 (viewport ≈ 970 m × 2150 m) and all 7 lots are 1.4–2.7 km away, so **no pin is visible** and no hint says where they are. The pins appear only after the user pans about 1.5 km west.
- **Screenshots:** `28-mp5-expanded.png` (after Expand), `30-mp5-panned-west2.png` (pins found after panning), `27-mp5-empty.png` (before).

## 4. Observations (not US-1.2 failures; for the main agent / US-1.1 owner)

- **O1 (US-1.1 AC6, Minor):** On an offline cold start (permission granted, device location **on**), Google Play services shows its dialog "For a better experience, turn on device location, which uses Google's location service" (`15-offline-coldstart.png`). After "No thanks", the app shows **"Location is off" + "Turn on"** although device location is on (`location_mode=3`, `17-online-again.png`). Tapping My location opens the Location settings. Coming back to the app, it recovers (blue dot, load). The app seems to treat the declined Google accuracy dialog as "location services off".
- **O2 (US-1.1 AC5, Minor):** After the 2nd denial (permission `USER_FIXED`) and a relaunch, the 1st tap on "Enable" does nothing visible (Android returns "denied forever" without UI). Only the 2nd tap opens the app settings page (`23-blocked-enable.png`).
- **O3 (info):** The log's `trigger=` has only two values, `position` and `area`. My location, Expand, Retry and the auto retry all log `trigger=position`. Retry/auto-retry can't be told apart from a new search in the log. This is enough for these tests, but a finer label would help QA.
- **O4 (NFR-8, needs a TalkBack check):** The uiautomator semantics dump sometimes lists only clusters and not the single pins or the open mini card, even though they are on screen (seen at MP-2 and after the area search at MP-4). Other times it lists them. This may be a dump timing artefact. It should be checked with real TalkBack (TC-1.2.22).
- **O5 (info):** The out-of-area banner pushes the "Search this area" chip down to y ≈ 475 (`42-mp6-area.png`). The chip still works. The empty-state message and the chip can show at the same time (`50-vi-empty-area.png`). The error banner stays visible while the auto retry is in flight, together with the spinner (`57-inflight-6.png`).
- **O6 (info):** The mini card stays open after a cluster tap, after a pan, and after returning from the detail screen. A new load closes it. "Go to Vũng Tàu" leaves the out-of-area banner visible. The spec doesn't say otherwise.

## 5. Open questions

- **Q1 (BUG-1 / AC4):** After "Expand to 3 km" returns lots, should the camera zoom out or fit the results (or show a hint such as "nearest lot 1.4 km")? AC4 only says "the same search is repeated with radius_m = 3000". TC-1.2.3 expects "≥ 1 pin shown". The PO / Tech Lead should decide and update AC4 or the test case.
- **Q2 (test data):** The cloud DB has only the 40 OSM lots. The local QA seed (≥ 60 lots at MP-2, motorbike/car mix, identical-coordinate pair) is local-only, so TC-1.2.6, .16 and .30 (and `hint_cap` in .21) can't run against the cloud build. Options: a debug build pointed at the local Supabase (emulator → `10.0.2.2:553xx`), or a PO decision to load test data elsewhere. Entry criterion Q-QA-23 is not met for a cloud run.
- **Q3 (AC5):** While the single auto retry is in flight, should the error banner stay ("Can't load parking lots" + Retry next to the spinner), or hide until the result? Tapping Retry during that time could start a second request.
- **Q4 (AC10 / TC-1.2.10):** The "timeout without last-known" run can't be reproduced on the emulator: a fix always arrives. It needs a real device indoors, or a widget test.
- **Q5 (O1):** Is declining the Google "Location Accuracy" dialog meant to show "Location is off"? US-1.1 AC6 only covers device location services being off.
